## 3. รายงานบั๊กและการปรับปรุง

| สิ่งที่พบ | ผลที่คาดหวัง | ปัญหาก่อนแก้ | การปรับปรุง |
|---|---|---|---|
| กด Ctrl+D ระหว่างกรอกเงินสด | ปิดโปรแกรมอย่างสุภาพ | เกิด `EOFError` traceback | ดัก `EOFError`/`KeyboardInterrupt` ที่ลูปหลัก |
| กรอกเบอร์สมาชิกผิด | แจ้งทันทีที่ช่องเบอร์ | ต้องกรอกข้อมูลช่องอื่นก่อนแล้วเริ่มใหม่ | ตรวจเบอร์ทันทีและถามซ้ำเฉพาะช่องนั้น |
| ข้อมูลใน RAM เปลี่ยนแต่บันทึกไฟล์ไม่สำเร็จ | RAM กับไฟล์ต้องตรงกัน | สถานะอาจไม่สอดคล้อง | rollback การเปลี่ยนแปลงเมื่อเขียนไฟล์ล้มเหลว |

## 4. Retrospective: Wow! & Whoops!

**Wow!**
- การแยก 3 เลเยอร์ทำให้เชื่อม CLI และทดสอบ Service ได้โดยไม่ผูกกับ Terminal
- การทดสอบ end-to-end ครอบคลุมเส้นทางขายตั้งแต่รับข้อมูลจนบันทึกออเดอร์
- Atomic write และ rollback ช่วยป้องกันไฟล์เสียและสถานะข้อมูลคลาดเคลื่อน

**Whoops!**
- การตรวจข้อมูลเฉพาะท้าย flow ทำให้ผู้ใช้ต้องกรอกข้อมูลซ้ำ
- ปรับให้ตรวจทันทีในแต่ละช่องและใช้ validator ร่วมกับ Domain Models
- การเขียน JSON ทุกครั้งเหมาะกับการใช้งานทีละรายการ; การนำเข้าข้อมูลจำนวนมากควรมี bulk operation
